Sección 01

Introducción

Codex es un asistente de inteligencia artificial para programar, creado por OpenAI. Codex se comunica con los modelos de IA a través de un sistema llamado Responses API (una forma estandarizada en la que una aplicación “habla” con un modelo de IA a través de internet).

Según la documentación oficial de DeepSeek, la API de DeepSeek es compatible de forma nativa con esa misma Responses API, lo que permite conectar los modelos de DeepSeek a Codex.

ℹ️
Info · Dato importante de la documentación oficial

Todos los clientes de Codex — es decir, Codex CLI (la versión de línea de comandos), la aplicación de escritorio de ChatGPT y la extensión de Codex para VS Code — comparten el mismo archivo de configuración. Esto significa que, según la fuente oficial, configurando ese archivo una sola vez, DeepSeek queda disponible en los tres clientes a la vez.

>_ Codex CLI 🗨 ChatGPT de escritorio </> Extensión VS Code = 1 configuración compartida
📖 Glosario · Variable de entorno / archivo de configuración

Un archivo de configuración es un documento de texto que un programa lee al arrancar para saber cómo debe comportarse (por ejemplo, qué modelo de IA usar). No hace falta modificar el código del programa: basta con editar ese archivo.

Este tutorial explica, siguiendo exclusivamente lo indicado por la documentación oficial, cómo preparar Codex para trabajar con DeepSeek V4.

Según lo que la documentación oficial menciona explícitamente:

Tener instalado Codex CLI o la aplicación de escritorio de ChatGPT, y haberlo abierto al menos una vez. Esto es necesario porque, según la fuente oficial, así se crea la carpeta ~/.codex en tu ordenador, que es donde se guardará la configuración.

📖 Glosario · Clave de API (API Key)

Es un código secreto y personal que identifica tu cuenta ante un servicio en internet. Sirve para que DeepSeek sepa quién está haciendo la petición y pueda facturarla o autorizarla. Nunca debe compartirse.

Sección 04 · Capítulo 3

Conceptos básicos

3.1 · ¿Qué es DeepSeek?

La documentación oficial no incluye, en el texto al que se pudo acceder de esta página concreta, una definición general de “qué es DeepSeek” como empresa o proyecto.

Lo que sí indica explícitamente es que DeepSeek ofrece una API que es compatible de forma nativa con la Responses API, y que por eso puede conectarse a Codex.

3.2 · ¿Qué es Codex?

Según la documentación oficial: “Codex is an AI coding assistant from OpenAI” — es decir, Codex es un asistente de inteligencia artificial para programar, desarrollado por OpenAI.

Se comunica con los modelos a través de la Responses API.

3.3 · ¿Qué significa integrar DeepSeek con Codex?

Según la fuente oficial, integrar DeepSeek con Codex significa configurar DeepSeek como “proveedor de modelo” (model provider) dentro del archivo de configuración compartido por todos los clientes de Codex.

Una vez hecho esto, Codex puede usar los modelos de DeepSeek “como si fueran uno de sus modelos integrados” (traducción del término oficial “just like its built-in models”, usado para explicar el propósito del archivo models.json).

📖 Glosario · Modelo (de IA)

Es el “cerebro” de inteligencia artificial concreto que responde a tus preguntas o genera código. Codex, por sí mismo, no es un modelo: es una herramienta que puede usar distintos modelos, entre ellos los de DeepSeek.

Instalación y configuración — Opción 1: Script automático

La documentación oficial ofrece dos caminos alternativos para esta configuración: un script automático (Opción 1, marcada como Recomendada por la documentación oficial) o la edición manual de archivos (Opción 2). En esta pestaña se explica la Opción 1.

1

Verifica que Codex ya se ha abierto una vez

Antes de ejecutar el script, la documentación oficial indica expresamente: “make sure Codex CLI or the ChatGPT desktop app is installed and has been launched at least once (so that the ~/.codex directory exists)”.

¿Qué acabamos de hacer? Nos hemos asegurado de que existe la carpeta donde Codex guarda su configuración, para que el script tenga dónde escribir.
2

Ejecuta el script oficial

Ejemplo oficial / documentado Según tu sistema operativo, la documentación oficial indica un comando distinto.

En macOS / Linux, ejecuta en la terminal:

bash · macOS / Linux
bash <(curl -fsSL https://cdn.deepseek.com/api-docs/codex-deepseek-setup-en.sh)

En Windows, ejecuta en PowerShell:

PowerShell · Windows
irm https://cdn.deepseek.com/api-docs/codex-deepseek-setup-en.ps1 | iex
¿Qué acabamos de hacer? Hemos descargado y ejecutado, en un solo paso, el script oficial de DeepSeek que configura Codex automáticamente. Estos comandos descargan el script directamente desde el dominio oficial de DeepSeek (cdn.deepseek.com) y lo ejecutan en el mismo paso.
📖 Glosario · Terminal / PowerShell

Son programas donde se escriben comandos de texto en lugar de hacer clic en botones. La Terminal se usa en macOS y Linux; PowerShell es el equivalente en Windows.

Elige el modelo desde el menú

Introduce tu clave de API

La documentación oficial indica: “On first run, the script asks for your API Key (starting with sk-; get one from the DeepSeek Platform)”.

¿Qué hace el script exactamente? (según la documentación oficial)

La fuente oficial detalla que el script realiza estos cuatro pasos internos. Pulsa cada uno para desplegarlo:

El archivo ~/.codex/config.toml se copia a ~/.codex/backup-deepseek/, de modo que puedas restaurarlo en cualquier momento.

Este archivo declara a Codex los metadatos de los modelos de DeepSeek (tamaño de la ventana de contexto, niveles de esfuerzo de razonamiento admitidos, formatos de llamada a herramientas, etc.), de forma que Codex pueda usar los modelos de DeepSeek igual que usa sus modelos integrados.

Solo se reescriben los campos necesarios, y se añade una sección [model_providers.deepseek]. Tus ajustes existentes, como los servidores MCP o los niveles de confianza de proyecto, se conservan. Si algún campo existente entra en conflicto con la configuración de DeepSeek, el script lo elimina e imprime en pantalla el motivo de cada eliminación.

El script comprueba la sintaxis de config.toml y de models.json antes de escribir; si la validación falla, el proceso se detiene sin modificar ningún archivo.

📖 Glosario · Sintaxis

Son las reglas de escritura que debe cumplir un archivo de configuración para que el programa pueda leerlo sin errores (parecido a la ortografía y la gramática, pero para un archivo de datos).

ℹ️
Verificación

La documentación oficial no proporciona, en el texto accesible, un procedimiento explícito de verificación para este paso; sí indica que el propio script realiza una validación de sintaxis antes de guardar cualquier cambio, y que aborta sin modificar archivos si esa validación falla.

💡
Ejemplo · Reutilización del script

Según la documentación oficial, puedes volver a ejecutar el script en cualquier momento para cambiar de modelo desde el menú, o para restaurar la configuración a su estado anterior a la instalación (opción 9 del menú).

Instalación y configuración — Opción 2: Edición manual

Paso 1 — Crea el archivo del catálogo de modelos ~/.codex/models.json

La fuente oficial indica: “First, create the model catalog file ~/.codex/models.json, which declares the metadata of DeepSeek models to Codex”.

Este archivo, según la documentación, es idéntico al que escribe el script automático de la Opción 1, y contiene tres modelos: deepseek-v4-flash, deepseek-v4-pro y deepseek-v4-flash-vision-exp.

Info · Detalle técnico explícito de la documentación

Sobre este archivo, la documentación oficial precisa explícitamente un detalle técnico: la entrada de deepseek-v4-flash-vision-exp declara "image" dentro de un campo llamado input_modalities, y es precisamente ese dato el que le indica a Codex que ese modelo concreto acepta imágenes como entrada.

El models.json que publica la documentación oficial es un archivo JSON muy extenso, que además incluye, dentro de cada modelo, un bloque de texto muy largo (las instrucciones internas por defecto de Codex). En su lugar, aquí tienes los campos documentados que sí son relevantes para el usuario, verificados directamente contra la fuente oficial:

Sección 13 · Capítulo 13

Resumen final y autoevaluación

13 · Resumen final

Según lo que se pudo verificar directamente contra la documentación oficial de DeepSeek:

  • Codex se comunica con los modelos a través de la Responses API, que DeepSeek admite de forma nativa.
  • Existen dos caminos oficiales para integrar DeepSeek con Codex: un script automático (recomendado por la propia documentación) o la edición manual de dos archivos (models.json y config.toml).
  • El script automático hace copia de seguridad, escribe el catálogo de modelos, modifica config.toml de forma selectiva y valida la sintaxis antes de guardar cualquier cambio.
  • Los modelos documentados son deepseek-v4-flash, deepseek-v4-pro y deepseek-v4-flash-vision-exp (este último, con entrada de imágenes).
